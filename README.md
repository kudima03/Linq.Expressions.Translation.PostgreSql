# Linq.Expressions.Translation.PostgreSql

Translates the expression tree of an `IQueryable<T>` into a single PostgreSQL `SELECT` statement.

## What is translated

- `Where`, `Select`, `OrderBy`/`OrderByDescending`/`ThenBy`/`ThenByDescending`, `Order`/`OrderDescending`, `Skip`, `Take`, `TakeLast`, `SkipLast`, `Distinct`, `DistinctBy`, `Reverse`, `Cast` and `OfType`; an operator that cannot extend the current `SELECT` (for example `Where` after `Take`) wraps it into a derived table, which exposes ordering keys the projection hides as extra `"$n"` columns so that the order survives (also for `Reverse`, `Last` and `TakeLast`). A later `OrderBy` sorts stably, as in LINQ to Objects: the keys of an earlier ordering follow its keys and those of its `ThenBy`. The ordering operators accept `StringComparer.Ordinal`, the order of UTF-16 code units: `COLLATE "C"` alone is the byte-wise order of UTF-8, the order of code points, which puts a character above U+FFFF (a surrogate pair in UTF-16, an emoji for example) after U+E000..U+FFFF where .NET puts it before them, so the key is the text with U+D7FF, the last character before the surrogates, put before every such character (`ORDER BY REGEXP_REPLACE(text, '([\U00010000-\U0010FFFF])', E'\ud7ff\\1', 'g') COLLATE "C"`). Without a comparer text is ordered by the collation of the database, where LINQ to Objects uses the current culture. A `double` or `float` key sorts NaN below every number, as .NET does and PostgreSQL does not: `ORDER BY NULLIF(key, 'NaN') NULLS FIRST`, or by `key = 'NaN'` first for a key that may be `NULL` as well. `DistinctBy` is `SELECT DISTINCT ON (keys)`, whose `ORDER BY` has to start with the keys: a source order that does not (`OrderByDescending(o => o.PlacedAt).DistinctBy(o => o.UserId)`, the latest order per user) is restored outside a derived table, into which every later operator other than a projection or paging also wraps the kept rows. `Distinct` yields the first occurrence of each value in the order of the source, as in LINQ to Objects: `SELECT DISTINCT` ordered by the selected values where they are ordered by themselves (`OrderBy(c => c.Region).Select(c => c.Region).Distinct()`), otherwise `DISTINCT ON` the values in the order of the source, restored outside as for `DistinctBy` (`OrderByDescending(c => c.Id).Select(c => c.Region).Distinct()` is `SELECT t1."Region" FROM (SELECT DISTINCT ON (t0."Region") t0."Region", t0."Id" AS "$0" FROM "Customer" AS t0 ORDER BY t0."Region", t0."Id" DESC) AS t1 ORDER BY t1."$0" DESC`).
- Comparison, logical, arithmetic, bitwise and conditional operators, `??`, conversions (a `DateTime` compares with a `DateTimeOffset` through PostgreSQL's session time zone; a `DateTime` is a `timestamp` inside the statement whatever its kind, as C# compares `DateTime` values, computes with them and reads their members by their ticks; one of the kind `Utc` — a constant, a value built with `DateTimeKind.Utc`, parsed as UTC or read from `UtcNow` or `UtcDateTime` — is converted to the UTC offset, a `timestamptz` (`... AT TIME ZONE 'UTC'`), only where it is read as a result or becomes a `DateTimeOffset`, so that it comes back with the kind `Utc`; a value that would be `Utc` on some rows and `Unspecified` on others, a conditional or `Max` of both for example, has no column type and is rejected where it is read), string concatenation, `Nullable<T>` members and constructed objects (`new Summary(c.Id, c.Name)`, also of constants only), which are projected member by member, as is a constant tuple (`default(ValueTuple<int?, string?>)` or a captured one, whose members become literals, `NULL` for a default). `string.CompareOrdinal(a, b)` compared with `0` is `a COLLATE "C" = b` or `<>`, and for `<`, `<=`, `>` and `>=` the comparison of the ordinal keys of both sides, ranking a null operand below every string as .NET does (`a IS NULL OR key(a) COLLATE "C" < key(b)`). A whole `decimal` or `double` constant is written with its point (`250.`), as PostgreSQL takes a number without one for an integer and divides integers without a remainder, unless a numeric operand beside it types it (`t0."Total" > 100`); a `float` constant is always `CAST(... AS real)`, beside which a `real` is not computed in double precision, and the negative zero is `CAST('-0' AS double precision)`. A `decimal` quotient and `Average` are computed to 30 places and rounded to the places a `System.Decimal` keeps (`TRIM_SCALE(ROUND(ROUND(a, 30) / b, 29 - LENGTH(CAST(TRUNC(ABS(...) / 0.79228162514264337593543950335) AS text))))`), where `numeric` alone stops at about 20 significant digits; sums, differences and products are exact in `numeric`, which has neither the 96 bits nor the range of a `decimal`, so a result past them is not rounded or refused. The operators `<`, `<=`, `>`, `>=` and `==` are false for NaN and `!=` true, as in .NET (`x > y AND x <> 'NaN'`; a constant other than NaN on the deciding side needs no guard), while `Equals`, `Distinct`, `GroupBy`, `Join` and `Contains` take NaN for equal to itself in both. A constant test decides a conditional, so the branch it never takes is not translated.
- `string` members (`Length`, case conversion, trimming (`Trim()` removes every .NET white-space character, not only spaces), `Substring`, `Remove`, `IndexOf`/`LastIndexOf`/`IndexOfAny`, `Replace`, `Contains`/`StartsWith`/`EndsWith` as `LIKE` with escaped wildcards, `IsNullOrEmpty`, `Concat`, `Format` and interpolated strings without alignment or format strings; lengths and positions count code points, as PostgreSQL does, not UTF-16 code units, so a character outside the Basic Multilingual Plane, an emoji for example, counts once instead of twice), `Math` functions (`Round` half to even, .NET's default, or away from zero, of decimals and doubles, also to digits) and their `int`/`long`/`decimal`/`double` counterparts, `double.IsNaN`/`IsInfinity`/`IsFinite`, date and time parts and arithmetic (`DateTime`, `DateTimeOffset`, `DateOnly`, `TimeOnly`), `TimeSpan` fields and totals (`Days`, `Hours`, ..., `TotalDays`, ..., `Ticks`), `DateTime.Now`/`UtcNow`/`Today`, `DateTimeOffset.Now`/`UtcNow`, `Guid.NewGuid`, `Enum.HasFlag` and `ToString` of numbers and `Guid`. `Encoding.UTF8.GetString(bytes)` reads a `byte[]` (`bytea`) as text, `CONVERT_FROM(..., 'UTF8') COLLATE "default"` (the collation of the database, as a text column has it; `convert_from` alone yields the `"C"` collation of the encoding's name, under which `UPPER` and `LOWER` map ASCII letters only), over which the text operations compose, and `Encoding.UTF8.GetBytes(text)` is `CONVERT_TO(..., 'UTF8')`; PostgreSQL fails on bytes that are no UTF-8 where .NET replaces them, other encodings and the partial overloads are rejected, and a `byte[]` constant is a `BYTEA '\x...'` literal. Ticks are 100 ns since `0001-01-01`: `DateTime.Ticks` and `TimeOnly.Ticks` come from `EXTRACT(EPOCH FROM ...)`, and `TimeSpan.FromTicks`, `AddTicks` and `new DateTime(ticks[, kind])` of a computed count become interval arithmetic in microseconds (PostgreSQL keeps no finer unit; the kind has to be a constant other than `Local`; ticks before `0001-01-01` or past `9999-12-31` fail on the server, as .NET throws). A `DateTime`, `TimeOnly` or `TimeSpan` constant finer than a microsecond is rejected, as it would be read back as another value, and a `TimeOnly` less another is the time elapsed on a circular clock, never negative. `Parse` of `bool` and `Guid`, and of numbers and `TimeOnly` with `CultureInfo.InvariantCulture` (plus a constant `NumberStyles`/`DateTimeStyles`), is `CAST(... AS boolean | uuid | bigint | numeric | ... | time)`: the text has to be in PostgreSQL's input syntax, which also accepts forms .NET rejects; the current-culture overloads are rejected, and so is a `NumberStyles` the cast cannot honour, one with `AllowHexSpecifier` or `AllowBinarySpecifier`, which would read another number, or one without the sign and the white space of `NumberStyles.Integer`, which the cast accepts whatever the style. `DateOnly.Parse` and `DateTime.Parse` with the invariant culture are `TO_DATE(..., 'MM/DD/YYYY')` and `TO_TIMESTAMP('+00 ' || ..., 'TZH MM/DD/YYYY HH24:MI:SS.US') AT TIME ZONE 'UTC'`, which read the invariant short date month first whatever the server's `DateStyle`, at the same cost as a cast: a month and a day of one or two digits, a four-digit year, any single separator (`1/2/2024`, `01-02-2024 10:30:00`, also with `.`), leading spaces and a 24-hour time that may be missing or lack its seconds, with a fraction of a second of up to six digits when the text has one (a seventh digit fails, as PostgreSQL cannot hold it); an AM/PM marker and anything else after the time are dropped, a two-digit year is the year itself (`1/2/24` is the year 24), and any other form, ISO 8601 or a month name for example, fails on the server. The fixed `+00` offset, taken back as UTC, keeps a `DateTime` as written even in a daylight-saving gap of the session's time zone. With `DateTimeStyles.AssumeUniversal | DateTimeStyles.AdjustToUniversal` the value is of the kind `Utc`: read as a result it is the `TO_TIMESTAMP(...)` itself, a `timestamptz`, the instant the text says in UTC, which Npgsql reads with the kind `Utc`; `AssumeUniversal` alone and `AssumeLocal`, which convert through or read in the local time zone of the client, are rejected, as the server does not know it.
- Dates and times built from parts: `new DateOnly(year, month, day)` is `MAKE_DATE(...)`, `new TimeOnly(hour, minute[, second[, millisecond[, microsecond]]])` is `MAKE_TIME(...)` with the seconds and their fraction added up exactly in `numeric`, `new TimeOnly(ticks)` is midnight plus the microseconds of the ticks (ticks that are not a whole number of microseconds fail), `new DateTime(year, month, day[, hour, minute, second[, millisecond[, microsecond]]][, kind])` is `MAKE_TIMESTAMP(...)`, `new DateTime(date, time[, kind])` and `DateOnly.ToDateTime(time[, kind])` are the date plus the time, and `DateOnly.FromDayNumber(n)` counts days from `0001-01-01`; a constant kind of `Utc` makes the value one of that kind, read at the UTC offset. They fail on the server where .NET throws: `MAKE_DATE`, `MAKE_TIME` and `MAKE_TIMESTAMP` reject an invalid month, day or minute themselves, and a year outside 1..9999, an hour of 24, a second of 60, a millisecond or microsecond above 999, ticks of a day or more and a day number past `9999-12-31` turn the year into 0 or the hour into -1, which they reject (`MAKE_DATE(CASE WHEN (t0."Year" >= 1) AND (t0."Year" <= 9999) THEN t0."Year" ELSE 0 END, ...)`; a constant part in range needs no guard, and a date or time of constants alone, one that failed to evaluate in a branch that may not be reached, reads its first part through a scalar subquery, so that PostgreSQL does not fold it, and fail, while it plans the statement). The `Calendar` overloads and the kind `Local` are rejected. `AddMonths` and `AddYears` keep the day, or the last day of a shorter month, as .NET does (`2024-01-31` plus a month is `2024-02-29`); past `9999-12-31` PostgreSQL keeps counting where .NET throws.
- `string.Join(separator, values)` joins a null separator or value as the empty string, as .NET does: an array of values is concatenated (`a || ', ' || COALESCE(b, '')`), an array column is `ARRAY_TO_STRING(..., separator, '')`, and the values of a group, a subquery or the group of a `GroupJoin` are `COALESCE(STRING_AGG(value, separator ORDER BY ...) FILTER (WHERE ...), '')` in the order the sequence's `OrderBy` gives, followed by the order of the source a group was grouped from (otherwise in no defined order, as the rows of a query without `ORDER BY`), so that an empty sequence is the empty string; a paged or distinct subquery is aggregated from a derived table that keeps its order, a captured `IQueryable<string>` is its subquery, an aggregate over values of the outer row alone (`Select(o => c.Name)`) reads them from a derived table, as PostgreSQL would otherwise take it for an aggregate of the outer query, and a separator that aggregates the group is applied outside the aggregate (`ARRAY_TO_STRING(ARRAY_AGG(...), separator, '')`). Distinct values of a group are `STRING_AGG(DISTINCT ...)`, which PostgreSQL orders by the value only, when they are never null and sorted by themselves or come in no order at all; in any other order they come by their first occurrences, as in LINQ to Objects: the values aggregated into an array in their order, unnested with their positions and grouped again (`ARRAY(SELECT u.v FROM UNNEST(ARRAY_AGG(value ORDER BY ...)) WITH ORDINALITY AS u (v, i) GROUP BY u.v ORDER BY MIN(u.i))`). Values of another type than `string` (`string.Join(",", ints)`, `object[]`) and the overloads with a start index are rejected, as PostgreSQL formats them differently.
- The elements of a group sorted with `OrderBy`/`OrderByDescending`/`ThenBy`/`ThenByDescending` (also with `StringComparer.Ordinal`): `First`, `FirstOrDefault`, `Last` and `LastOrDefault` of a selected value, also with a predicate, are the first element of `ARRAY_AGG(value ORDER BY ...) FILTER (WHERE ...)` in that order or in the inverted one (`(ARRAY_AGG(t0."Total" ORDER BY t0."CreatedAt", t0."Id"))[1]`). The elements of a group come in the order of the source it was grouped from, which follows the keys the group is sorted by and breaks their ties, so that `Last` of a descending order is the last of the tied elements, and a group of an ordered source needs no `OrderBy` of its own; elements that tie on every key of a group of an unordered source come in no defined order, and `First` of such a group that is not sorted is any of its elements, as for a query. `Last` of the distinct values of a group is the value that first occurs the latest. A filtered group may hold no element: `FirstOrDefault` and `LastOrDefault` substitute the default of a value type there, and `First` and `Last` with a filter or a predicate are rejected, as .NET throws. `Min` and `Max` of strings with `StringComparer.Ordinal`, over a group or a query, are `MIN` and `MAX` of the ordinal keys, read back as the text in the collation of the database.
- `new[] { a, b, ... }.Max()` and `Min()` (`Enumerable` or `MemoryExtensions`) are `GREATEST(a, b, ...)` and `LEAST(...)`, which skip NULLs and are NULL only when every value is, as `Max` and `Min` of nullable values are, for numbers other than `double` and `float`, `bool`, enums, dates, times, durations and, with `StringComparer.Ordinal`, strings (`LEAST` of their ordinal keys, read back as the text). `Max` and `Min` of `new T[n]` are the default of `T` for a length above zero, and of a captured array they are folded into their value. `string.Normalize()` and `Normalize(form)` with a constant form are `NORMALIZE(text, NFC | NFD | NFKC | NFKD)`, which needs a UTF-8 database; .NET normalizes with the ICU of its host and PostgreSQL with the Unicode tables it was built with (Unicode 16.0 for PostgreSQL 18, 15.1 for the ICU 74 of Ubuntu 24.04), which agree on every character both versions assign: a character assigned only in the later version may be normalized by one and kept by the other.
- `Contains` (and `Any(x => x == value)`) on in-memory collections (`IN (...)`) and on array columns (`= ANY (...)`, which is `COALESCE(..., FALSE)` as a value or under `NOT`, as an array may hold `NULL` elements), plus array `Length`, `Count()` and `Any()`. `Contains` of a tuple or an object of values in a sequence of them is the `EXISTS` of a row whose members equal its members, a null member equal to a null one. The other `Enumerable` operators over an in-memory collection, or over a table or a query read as `IEnumerable<T>` (also after `ToList`, `ToArray`, `AsEnumerable` or `AsQueryable`), are the `Queryable` operators of the same name over its `VALUES` list or its subquery: `ids.All(y => y != c.Id)`, `ids.Where(y => y < c.Id).Sum()`, `orders.ToList().Contains(c.Id)`.
- Terminal operators: `Count`/`LongCount`, `Sum`, `Average` (of integers the exact mean, `CAST(AVG(x) AS double precision)`; of decimals to the places of a `System.Decimal`), `Min`, `Max` (of booleans as `BOOL_AND`/`BOOL_OR`; of `double` and `float` as `-MAX(-x)` and `-MIN(-x)`, which are NaN when any value, or every value, is, as in .NET; `Min`/`Max` of `Guid` is rejected, as PostgreSQL orders uuids differently), `MinBy`/`MaxBy` (the first row in the order of the key, `NULLS LAST` so that elements with a null key are skipped unless every key is null, and then of the source, so that ties resolve as in .NET; `StringComparer.Ordinal` gives `COLLATE "C"`, and a `Guid` key is rejected like `Min`/`Max` of `Guid`), `Any`, `All`, `Contains`, `First`/`Single`/`Last`/`ElementAt` (and their `OrDefault` forms, which substitute the default of a value type inside a lambda; `ElementAt(^n)` reads the inverted order at `OFFSET n - 1`), and aggregates after `DefaultIfEmpty()`. `DefaultIfEmpty()` and `DefaultIfEmpty(value)` as a sequence operator, and the default given to `FirstOrDefault`, `LastOrDefault` or `SingleOrDefault`, are one row left joined to the rows (`SELECT COALESCE(t1."Quantity", -1) FROM (SELECT 1) AS t2 LEFT JOIN (...) AS t1 ON TRUE`); a given default of a value that may be `NULL` in a row is told from the absence of a row by a hidden `"$present"` column.
- The same operators inside lambdas, as correlated or uncorrelated subqueries (`EXISTS`, `IN (SELECT ...)`, scalar subqueries). An aggregate (`Count`, `Sum`, `Average`, `Min`, `Max`, `Any`, `All`) in the projection of a query over the rows that projection reads — the same query, in any order, below any `Where` and `Select` of the aggregate's own — is a window aggregate over all of them, computed in the pass that reads the rows: `orders.Select(o => new { o.Id, Share = o.Total / orders.Sum(x => x.Total) })` is `SELECT t0."Id", t0."Total" / COALESCE(SUM(t0."Total") OVER (), 0) AS "Share" FROM "Order" AS t0`, and a filtered one is `COUNT(*) FILTER (WHERE ...) OVER ()`. The rows have to be the rows the projection reads (not once they are paged or made distinct) and the aggregate's lambdas must read nothing but their own element, otherwise it stays a scalar subquery; a filter, grouping, join or aggregate over a projection holding a window wraps it into a derived table, as SQL allows a window only in a projection, an order, paging or `DISTINCT`, and an aggregate of what a window function computes stays a subquery, as PostgreSQL nests no window in another.
- `Join` (`INNER JOIN`; keys compare with `=`, so null keys never match, as in C#, while the members of a composite key, an anonymous type or a tuple that compares its members with the default comparer, match with `IS NOT DISTINCT FROM` when both are nullable), `GroupJoin` (aggregated groups as correlated subqueries, also after `Where`, `Select`, `OrderBy`, `Distinct` or paging of the group, or `LEFT JOIN` with `SelectMany`/`DefaultIfEmpty`, where a `Where` on the group before `DefaultIfEmpty()`, possibly chained, becomes part of the `ON` condition instead of dropping the unmatched rows) and `SelectMany` (`CROSS JOIN`, correlated `INNER`/`LEFT JOIN`, or a derived table when the inner source is paged or windowed, `JOIN LATERAL` if it, or a recursion, also reads the outer element). A left-joined source that projects anything other than its own columns (a computed value, a constant, a column of the outer element) is joined as a derived table, so that an unmatched row reads it as `NULL`, as the default element is in LINQ to Objects, instead of evaluating it on the `NULL`s of the missing row. An outer row without a match reads the element `DefaultIfEmpty()` yields: `null` for a reference type (such a projection compared with `null` tests a column that is never `NULL` in a match, or every column when there is none, as a left-joined entity does), the default of a value type member by member (`COALESCE(..., 0)`, down to a reference or nullable member, which stays `NULL`), or the explicit default of `DefaultIfEmpty(value)`, which is translated only for a single value that is never `NULL` in a match, as `NULL` cannot be told from the absence of a row.
- `GroupBy` (with element and result selectors): `GROUP BY` the flattened key, `HAVING` for filters on groups, and aggregates over the group — `Count` (also with a predicate, as `FILTER (WHERE ...)`), `Sum`, `Average`, `Min`, `Max`, `Any`/`All` (`BOOL_OR`/`BOOL_AND`), `Where(...)` (possibly chained) before an aggregate and `Select(...).Distinct()` before `Count`, `Sum` or `Average` (`COUNT(DISTINCT ...)`, `SUM(DISTINCT ...)`, `AVG(DISTINCT ...)`; `Select` after `Distinct` is rejected, as the aggregate would apply to the distinct projected values). Over an ordered source the groups come in the order of the first element of each, as in LINQ to Objects: `ORDER BY` the key itself when it is a grouping key, `MIN`/`MAX` of a first ordering key that is never `NULL`, and otherwise the key of the group's first element in the order, `(ARRAY_AGG(key ORDER BY ...))[1]`.
- `Concat`, `Union`, `Intersect` and `Except` as `UNION ALL`, `UNION`, `INTERSECT` and `EXCEPT`, parenthesizing operands that are paged or a different set operation. `Concat` of an ordered side yields the first sequence in its order and then the second in its, as in LINQ to Objects: the sides are combined under a hidden `"$side"` column and the ordering keys of each, exposed as hidden columns that are `NULL` on the other side, and read from a derived table ordered by the side and then the keys; `Union`, `Intersect` and `Except` yield no order. `UnionBy` is `SELECT DISTINCT ON (keys)` over both sides combined with `UNION ALL`, each marked with a hidden `"$side"` column, ordered by the keys and then the side, so that the element of the first sequence is the one kept, as in .NET; the result has no order, like `Union`. `IntersectBy` and `ExceptBy` filter the elements on the membership of their key in the second sequence, a subquery (`IN (SELECT ...)`) or an in-memory collection of keys (`IN (...)`), with the null semantics of `Contains` (a null key matches a `NULL` of the sequence), and keep one element per key with `DISTINCT ON`, as `DistinctBy` does.
- Captured variables and parameter-free subtrees, which are evaluated in memory and rendered as literals. A subtree that throws when it is evaluated where it may not be reached (a branch of a conditional, the right operand of `??`, `&&` or `||`) is left to the database with the constants below it folded: `o.Id < 0 ? one / zero : o.Total` with `zero == 0` is `CASE WHEN t0."Id" < 0 THEN (SELECT 1) / 0 ELSE t0."Total" END`, where the scalar subquery keeps the planner from computing the division while it plans the statement, as PostgreSQL folds an operation on constants alone before any row reaches it. Elsewhere the exception propagates from the translation.
- One row of aggregates over tables: a constant one-element sequence as the root (`new[] { 0 }.AsQueryable().Select(_ => new { Orders = orders.Count(), Revenue = orders.Sum(o => o.Total) })`) is a `SELECT` of scalar subqueries without `FROM`, as long as the element is not read; once it is, by a lambda or as a sequence that is joined, combined, ordered or searched, the sequence is a `VALUES` list of its one row, as a longer one is. Joined on either side (`SelectMany`, `Join`, `GroupJoin`), the row is a derived table, which puts the totals next to every row: `customers.SelectMany(c => totals, (c, t) => new { c.Name, t.Orders })` is `FROM "Customer" AS t0 CROSS JOIN (SELECT (...) AS "Orders") AS t2`.
- In-memory sequences of scalars or of tuples of scalars (`ValueTuple` or `Tuple`, nested or of more than seven members) as a source: a root of two or more elements, the inner sequence of `Join`, `GroupJoin` or `SelectMany`, the second sequence of `Concat`, `Union`, `Intersect` or `Except`, or a subquery over one (`new[] { 1, 2 }.AsQueryable().Any(i => i == c.Id)`), are a `VALUES` list with a row per element, its columns named as a derived table's (`Value` for a scalar, `Item1`, ..., `Rest.Item1` for a tuple): `customers.Join(labels, c => c.Id, l => l.Id, (c, l) => new { c.Name, l.Label })` with `labels` an array of `(int Id, string? Label)` is `SELECT t0."Name", t1."Item2" AS "Label" FROM "Customer" AS t0 INNER JOIN (VALUES (1, CAST('one' AS text)), (2, NULL)) AS t1 ("Item1", "Item2") ON t0."Id" = t1."Item1"`. The first row writes the type of every column whose literal does not (`bigint`, `numeric`, `double precision`, `text`, a `NULL`), so that a `long` is not summed as an `integer`, a whole `decimal` is not divided as one and a column of `NULL`s compares with any column of its type; a column holding no `NULL` is not nullable. `SelectMany` from the one-element root to an in-memory sequence it does not read (`new[] { 0 }.AsQueryable().SelectMany(_ => rows, (_, row) => row)`) is that sequence. A `byte`, `sbyte` or unsigned integer is the narrowest PostgreSQL type that holds every value of it (`smallint`, `integer`, `bigint`, `numeric` for a `ulong`) and a `char` a text of one character, compared with a number by its code (`ASCII`); a conversion to a `byte` or an unsigned integer, which wraps in C#, is rejected, except that of a signed integer to a `ulong`. The sequence has an order, which `VALUES` keeps only while its rows are read as they are: its positions are a column of the list, `"$position"`, written only when the statement reads it, to break the ties of a sort of the sequence or of rows joined to it, to take the first of its distinct values or groups, and to read `Last`, `TakeLast` or `Reverse` of it. An empty sequence, a null tuple and an element of any other type (an entity, an anonymous type, an array) are rejected, and so is a sequence computed from the outer element of `SelectMany` (`c => new[] { c.Id, c.Id + 1 }`).

- PostgreSQL features LINQ has no operator for, through the marker methods of [the PostgreSQL markers](#postgresql-markers): window functions over `OVER (PARTITION BY ... ORDER BY ... frame)` (`PostgreSqlWindows`, `PostgreSqlFrame`), `WITH RECURSIVE` with an optional depth limit that fails instead of cutting off (`PostgreSqlRecursion`).

Anything else — user-defined methods, culture- or comparison-specific overloads, `Max` and `Min` of an array of `double`, `float`, `Guid` or `char` values, or of strings without `StringComparer.Ordinal` (PostgreSQL orders NaN, uuids and text otherwise), `string.Join` of values other than strings, `Last` of a group that has no order, a text with a lone surrogate or the NUL character, columns whose names share their first 63 bytes (all PostgreSQL keeps of a name), navigation properties, in-memory sources other than those above, operators such as `Zip`, `Aggregate` or `SkipWhile` — throws `NotSupportedException` naming the offending member, method or expression node.

## Overview

The package exposes one public type that translates, `PostgreSqlQuery`, and the [PostgreSQL markers](#postgresql-markers), which only mark PostgreSQL's SQL in a tree. `PostgreSqlQuery` accepts a `System.Linq.Expressions.Expression` — the `Expression` of an `IQueryable<T>` — and exposes the PostgreSQL `SELECT` statement for that tree as its `TextValue`.

```csharp
IQueryable<Order> orders = ...; // any IQueryable<T> whose provider builds the tree

string sql = new PostgreSqlQuery(
    orders.Where(o => o.Total > 100).Select(o => o.Id).Expression
).TextValue;

// SELECT t0."Id" FROM "Order" AS t0 WHERE t0."Total" > 100
```

The package does not execute queries, open connections or materialize results; it only produces SQL text.

## PostgreSQL markers

PostgreSQL features that LINQ cannot express are written with marker methods, as `EF.Functions` is: they are named after PostgreSQL, follow PostgreSQL's semantics, exist only in expression trees (a lambda, or `Expression.Call` for a query operator outside one) and throw `NotSupportedException` when they are called, so that a provider that evaluates closed subtrees keeps the call in the tree.

| Type | Members | PostgreSQL |
|---|---|---|
| `PostgreSqlWindows` | `Over(source, partitionBy, orderBy, frame, (row, window) => ...)` | `SELECT ..., f(...) OVER (PARTITION BY ... ORDER BY ... frame) FROM source` |
| | `RowNumber`, `Rank`, `DenseRank`, `PercentRank`, `CumeDist`, `Ntile(buckets)` | `ROW_NUMBER()`, `RANK()`, `DENSE_RANK()`, `PERCENT_RANK()`, `CUME_DIST()`, `NTILE(n)` |
| | `Lag` / `Lead(value, offset, default)`, `FirstValue(value)`, `LastValue(value)` | `LAG(value, offset[, default])`, `LEAD(...)`, `FIRST_VALUE`, `LAST_VALUE` |
| `PostgreSqlWindow<TSource>` | `Rows`: the rows of the frame, which LINQ's `Count`, `LongCount`, `Sum`, `Average`, `Min`, `Max`, `Any` and `All` aggregate (after `Where`, as `FILTER (WHERE ...)`, and `Select`) | `COUNT(*) FILTER (WHERE ...) OVER (...)`, ... |
| `PostgreSqlFrame` | `Rows(start, end)`, `Range(decimal? start, decimal? end)`, `Range(TimeSpan? start, TimeSpan? end)`, `RangeMonths(start, end)`; `TextValue` | `ROWS` / `RANGE BETWEEN ... AND ...` |
| `PostgreSqlRecursion` | `WithRecursive(seed, level => step)`, `WithRecursive(seed, level => step, maxDepth)` | `WITH RECURSIVE r AS (seed UNION ALL step) SELECT ... FROM r` |

```csharp
// The two largest orders of each customer, with a running total from the largest. This is
// the tree a provider or a tree rewriter builds with Expression.Call (inside a lambda the
// compiler builds it): called as code, Over throws.
orders
    .Over(
        o => o.CustomerId,
        rows => rows.OrderByDescending(o => o.Total).ThenBy(o => o.Id),
        PostgreSqlFrame.Rows(null, 0), // ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
        (o, w) => new Ranked(o.Id, w.RowNumber(), w.Rows.Sum(x => x.Total))
    )
    .Where(r => r.Number <= 2);

// SELECT t1."Id", t1."Number", t1."Running" FROM (SELECT t0."Id", ROW_NUMBER() OVER (PARTITION BY
// t0."CustomerId" ORDER BY t0."Total" DESC, t0."Id" ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
// AS "Number", COALESCE(SUM(t0."Total") OVER (PARTITION BY t0."CustomerId" ORDER BY t0."Total" DESC,
// t0."Id" ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW), 0) AS "Running" FROM "Order" AS t0) AS t1
// WHERE t1."Number" <= 2
```

- **Windows.** `Over` yields one result per row of its source, in its order, computed after `WHERE`, joins and `GROUP BY` (a window over the groups of the same `SELECT` may aggregate them) and before `DISTINCT`, `ORDER BY` and paging; a paged, distinct or windowed source is wrapped into a derived table, and so is the result for a filter, a grouping, a join or an aggregate. The partition is one value, a tuple or an object of values (constants dropped), or `null`; the order is `OrderBy` or `Order` of the window's rows followed by `ThenBy`, which sorts as everywhere else in .NET's order (nulls first ascending, NaN below every number, `StringComparer.Ordinal` by UTF-16 code units); a `null` frame is PostgreSQL's default (with an order, `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`, the current row's peers included). A frame bound is an offset from the current row: negative `PRECEDING`, positive `FOLLOWING`, `0` `CURRENT ROW`, `null` `UNBOUNDED`; a duration is written in seconds (elapsed time, also over a `timestamptz`), `RangeMonths` in calendar months. A `RANGE` with an offset needs exactly one sort key of a matching type (a number, or a date, time, timestamp or interval); over an integer key, where PostgreSQL takes no numeric offset, a fraction is the next whole offset inside the frame, which holds the same keys, and an offset past a `bigint`, more rows than a `bigint` counts or more months than an interval holds is the largest PostgreSQL takes. The lambdas of the functions and of the aggregates over `Rows` read only their own row (SQL cannot name the current row inside an aggregate), the `default` of `Lag` and `Lead` is read in the current row, and the window may not be read in a lambda or a subquery of the selector. PostgreSQL nests no window function in another: an aggregate of a table in an argument is a subquery, a default of `Lag` or `Lead` that is a window function is read beside it (`COALESCE(LAG(value, offset) OVER (...), default)`, for a value that is never `NULL`), and a window function in any other argument is rejected, to be computed in an `Over` of its own first. A window over `DistinctBy` or `UnionBy`, or joined as an inner sequence, is one over a derived table. `Lag` and `Lead` take PostgreSQL's three arguments, the default standing for a missing row (a `null` default is PostgreSQL's own and is left out: `LAG(value, offset)`), so with a `null` default they read a nullable value; `FirstValue` and `LastValue` of a frame that may not hold the current row may find no row, where they are `NULL`, so they also have to read a nullable value. The aggregates over `Rows` keep .NET's semantics, as over a group (`Sum` is 0 and `Any` false over no rows); `DISTINCT`, which PostgreSQL has not implemented for window aggregates, is refused.
- **Recursion.** `WithRecursive` is a derived table `(WITH RECURSIVE r AS (seed UNION ALL step) SELECT ... FROM r) AS t`: every row of every level, duplicates included, in no order; a cycle ends where the step's own predicate stops it (a path column, for example). The step's parameter is the level before, which it reads exactly once, in `FROM` or an inner join, never in a subquery, a derived table or on the optional side of an outer join, and the step does not group, as PostgreSQL requires of the recursive term; its columns are matched to the seed's by their exact names, and only then by a name that differs in case, and a constant of the seed, a null or empty array included, is cast to its type (`CAST(0 AS numeric)`), as the seed decides the types of the columns. With `maxDepth` (the seed is level 0), a hidden `"$depth"` column counts the levels and a row deeper than the limit fails the statement with `invalid input syntax for type bigint: "WITH RECURSIVE: a row deeper than the maximum depth of n"`: PostgreSQL has no `RAISE` in SQL, so the step casts that message, read by a scalar subquery the planner does not fold, to `bigint` in the branch of a `CASE` that only such a row reaches. A one-time filter, `WHERE (SELECT COUNT(*) FROM r) > 0`, computes every level before the first row is read, as PostgreSQL computes a recursive query only as far as its reader asks; so a query that reads only some of the rows (`Take`, `Any`, `First`) fails as one reading all of them does, and a walk over cyclic data always ends. PostgreSQL computes no recursion it can tell no row will be read of, under a constantly false filter or joined to a side without rows, and the limit does not fail there.

## Mapping

A table is named after the element type and its columns after its public properties with a public getter (indexers and write-only properties are skipped), in declaration order. `[Table]` (including its `Schema`), `[Column]` and `[NotMapped]` from `System.ComponentModel.DataAnnotations.Schema` override the defaults. Identifiers are always double-quoted, so their case is kept. A property whose type is not a scalar (or an array of scalars; a `byte[]` is a `bytea`) is rejected, so navigation properties are not supported. A `byte`, `sbyte` or unsigned integer is a column of the narrowest PostgreSQL type that holds its values.

Nullability follows the CLR: `Nullable<T>`, nullable reference types and references without nullable annotations are nullable columns, and so are a conditional with a nullable branch, a scalar subquery or `Min`/`Max` of a reference type, a column of a set operation that is nullable on either side and every column of a left-joined source. A nullable value read as its value, `Nullable<T>.Value` or a cast `(T)nullable`, is never NULL where the C# evaluates (it would throw), so it compares and joins with `=`, also as a member of a composite key. C# semantics are preserved where SQL differs — equality with a nullable operand uses `IS [NOT] DISTINCT FROM` (a correlation key may still be compared with `=`, which is false for NULL in both languages, and so are the keys of `Join` and `GroupJoin`, which never match null keys; the members of a composite key do), a nullable comparison used as a value becomes `COALESCE(..., FALSE)`, nullable keys sort as `NULLS FIRST` ascending, membership tests used as a value or under `NOT` become `COALESCE(..., FALSE)` (`IN` of a nullable value, `= ANY` of any value, as an array may hold `NULL` elements), a nullable string or number is concatenated as `COALESCE(..., '')`, a lifted `^` of booleans stays NULL, `Contains` of a nullable item against a subquery or an array column also matches a NULL of the sequence (`Contains(null)` is true for a sequence holding a null), a left-joined entity compared with `null` tests a column its table requires (or every column), `Select(...).Distinct().Count()` over nullable group values counts NULL as one of them, and `OfType<T>()` drops the nulls of a nullable sequence. Concatenating a `bool`, an enum or a date or time value is rejected, as PostgreSQL formats them differently from .NET.

## Constants are inline literals

The result is a single string, not a command with a parameter collection. Every constant in the tree — literals, captured variables and in-memory collections — is rendered as a safely escaped inline PostgreSQL literal (for example, `'O''Brien'` for the string `O'Brien`; control and non-space white-space characters become `E''` escapes such as `E'a\u00a0b'`). No bind parameters (`$1`, `@p0`) are produced.

## Native AOT and trimming

The package is marked `IsAotCompatible` and builds without trimming or AOT warnings. Translation reads the public properties of the queried element types to find their columns, so `TextValue` is annotated `[RequiresUnreferencedCode]`: in a trimmed or Native AOT application a property that the code never references is removed, and its column silently disappears from `SELECT`. Keep the properties of every mapped type and then acknowledge the `IL2026` warning at the call site, for example:

```csharp
[DynamicDependency(DynamicallyAccessedMemberTypes.PublicProperties, typeof(Order))]
[UnconditionalSuppressMessage("Trimming", "IL2026", Justification = "Order properties are preserved.")]
static string Sql(IQueryable<Order> orders)
{
    return new PostgreSqlQuery(orders.Expression).TextValue;
}
```
